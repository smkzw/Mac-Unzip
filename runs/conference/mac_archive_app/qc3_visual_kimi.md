## 视觉 Go/No-Go

**当前状态：No-Go（修订后可通过）。**

理由：该图像是一张高完成度的电商 Dashboard 风格插画，而不是 macOS Finder/归档应用的真实界面。它无法直接作为视觉基准指导 SwiftUI/AppKit 实现。主要问题：

- 图中没有压缩包、没有归档相关语义、没有 macOS 原生窗口结构；
- 侧边栏、表格、检查器、工具栏的关系与规格要求的 Finder 式原生结构不符；
- 颜色、字体、控件、间距都不是 macOS 系统默认，开发者会陷入“临摹像素”而非“实现系统组件”；
- 媒体预览模式完全没有出现，无法用来验收 4.3 节设计目标；
- 没有提供暗色/降低透明度/2x 缩放下的可验收变体。

修订通过标准：提供一个 macOS 原生风格的合成视觉目标（至少包含浅色/暗色两张、列表视图与媒体预览视图两张），并给出标注层级与动态行为的线框/标注稿。

## 像素层级与原生性缺陷

### 1. 窗口外壳：非 macOS 原生

| 图中现状 | 设计规格要求 | 风险 |
|---|---|---|
| 全屏黑底、无标题栏分隔 | 原生标题栏与可自定义工具栏（4.1） | 难以用 SwiftUI `NavigationSplitView` + AppKit `NSToolbar` 直接还原；需要大量自定义窗口 chrome |
| 无交通灯按钮 | 设计规格未明说，但 macOS 原生窗口必须具备 | 用户会觉得这是 Web/Electron 应用，不是原生 App |
| 全局左侧窄边栏，图标+标签垂直排列 | Finder 式侧边栏分组与 disclosure（4.1） | 缺少分组标题、收藏、最近使用、操作记录等结构；缺少 `NSTableView` 分组样式 |
| 没有搜索框位置，仅有占位“Search…” | 工具栏搜索字段（6.1） | 无法判断搜索触发、聚焦、结果展示 |
| 无返回/前进、面包屑、视图切换控件 | 路径上下文与视图切换（4.1 / 4.4） | 核心导航功能缺失 |

### 2. 内容表格：像 Tailwind UI 而非 AppKit Finder

| 图中现状 | 设计规格要求 | 风险 |
|---|---|---|
| 5 行静态数据，无表头行 | 层级表格、可展开文件夹、可排序列、可调整列宽（4.2） | 无法验证表格可缩放、虚拟化、滚动、列重排 |
| 表头为纯灰色大写 | macOS 列表列标题 | 与系统 `NSOutlineView`/`Table` 默认样式不一致，需要额外自定义且容易失效 |
| 行与行之间无斑马纹/悬停/选择状态 | 选择、焦点、键盘导航（24） | 静态图像无法验证 VoiceOver/键盘/选择模型 |
| 客户名为绿色 | 设计规格仅允许系统强调色用于交互/状态，且要求不只靠颜色表达 | 会违反辅助功能原则；且与“完成/成功”绿色状态徽章混淆 |
| 状态徽章为圆角 pill | 与 macOS 原生标签/徽章风格不同 | 可自定义，但需为每个状态（加密、暂存、错误、只读）单独设计，维护成本高 |

### 3. 检查器/预览：完全缺失

规格要求右侧可折叠、可调整宽度的检查器，包含 Quick Look 预览和条目信息（4.2）。图中没有右侧边栏，无法验证：

- 检查器折叠/展开手势；
- 预览与信息的分段；
- 媒体预览时检查器是否浮出/停靠（4.3）。

### 4. 媒体预览模式：完全缺失

图中没有大尺寸预览、底部 filmstrip、媒体条键盘导航。这直接违反 4.3 节的核心目标。当前视觉目标无法用于验收媒体预览模式。

### 5. Liquid Glass：图中不存在，但会被误用

图中只有纯黑背景与亮绿强调色。如果开发者以此为“视觉方向”，很可能会把整张图当作“深色模式”：

- 没有标题栏/工具栏毛玻璃；
- 没有侧边栏材质；
- 没有检查器边缘模糊。

这意味着 4.5 节对 Liquid Glass 的限制没有视觉化依据，实现时容易过度或不足。

## 自适应布局与实现风险

### 1. 单一固定尺寸，无法验证响应式

图像是固定宽高静态图。规格要求：

- 小窗口可用；
- 检查器可折叠；
- 侧边栏可显隐；
- 列表/媒体视图切换不丢失状态；
- 2x 缩放不截断核心操作。

静态单图无法证明这些。建议补充：最小窗口、检查器收起、侧边栏收起、媒体预览、小尺寸窗口五种布局稿。

### 2. 字体与度量不可工程化

图中使用“大数字 KPI”风格的字体层级，而规格要求：

- 中文宋体/系统字体（设计规格 7/24）；
- 200% 文本缩放不截断；
- 长繁体/英文名称完整显示。

当前图像没有给出字体字号，无法转化为 SwiftUI `.font(.system(size: ...))` 或动态类型策略。需要补充 Typography spec。

### 3. 绿色强调色与系统强调色冲突

图中使用固定 `#00FF00` 风格亮绿，而 macOS 强调色由系统设置决定。规格 4.5 要求使用系统强调色。如果硬性使用固定绿色，会导致：

- 用户在系统强调色为蓝/红/紫时，看到不一致；
- 辅助功能增强对比模式下颜色可能失效。

建议：视觉目标应展示系统强调色为“默认绿”时的效果，并在文字中说明可随系统强调色变化。

### 4. 电商 Dashboard 隐喻与归档应用语义冲突

- “Total Revenue / Active Customers / Conversion Rate” 属于电商，不是归档应用；
- “Recent Orders” 与压缩包条目列表无关；
- 这种隐喻会让设计师把精力放在 KPI 卡片上，而不是文件大小、压缩率、加密状态、路径层级等归档应用特有的信息密度。

风险：下游实现会优先复刻 Dashboard 的“漂亮卡片”，而忽视归档工作台需要的“高密度信息表格”。

## 暗色辅助功能与缩放风险

### 1. 暗色模式推断

图像是黑底，但设计规格要求同时支持浅色和暗色（4.5 / 24）。当前图像无法判断：

- 暗色模式下表格行悬停/选择/交替背景的区分度；
- 侧边栏在暗色下的材质（sidebar / .ultraThinMaterial）；
- 检查器在暗色下的边缘层级；
- 状态徽章在暗色下的对比度（黄色 Pending 在暗色下可能过亮，红色 Cancelled 可能过暗）。

建议：提供暗色模式变体，并实测 WCAG 对比度 ≥ 4.5:1（正文）和 ≥ 3:1（组件）。

### 2. 降低透明度/增强对比度

规格 4.5 要求不手工模仿玻璃。图中没有玻璃材质，因此无法验收该系统回退行为。如果开发者直接实现为黑底，在降低透明度模式下没有问题，但会牺牲 Finder 原生感。

### 3. 2x 显示缩放与文字缩放

图中字号：标题 28–32px、数字 36–48px、表格正文 14–16px。在 2x 缩放或 200% 文本缩放时：

- 标题可能过大；
- 侧边栏可能只剩图标；
- 表格列可能无法完整显示“压缩后大小”等长中文标签；
- 搜索框可能过窄。

需要补充紧凑布局稿。

### 4. 绿色文本的色盲风险

绿色客户名与绿色 Completed 徽章对红绿色盲用户不可区分。规格要求“不只用颜色表达状态”。当前图像违反此原则，需要改为：

- 客户名恢复为白色/强调色链接；
- 状态徽章配合图标或文字前缀。

## 分级修改与验收清单

### P0 — 阻断（必须修正才能进入实施）

1. 替换当前电商 Dashboard 图像为真正的 macOS Finder 风格归档应用视觉目标。新图必须包含：原生标题栏/交通灯、工具栏、侧边栏、内容列表、右侧检查器/预览、底部状态栏。
2. 提供媒体预览视图稿：左侧目录树、中央大预览、底部 filmstrip、右侧检查器。
3. 提供列表/媒体视图切换的状态，并标注“切换时不丢失选择/滚动/搜索条件”。
4. 提供浅色、暗色两套变体，或至少说明暗色/浅色策略基于系统外观。
5. 将 KPI 卡片式数字区移除，改为符合归档应用的信息密度（文件大小、压缩后大小、压缩率、条目数、状态）。

### P1 — 高风险（修正后显著提升可实施性）

1. 给出侧边栏分组结构：最近使用、收藏位置、操作记录、当前压缩包目录树，每组标注系统材质/字体。
2. 给出表格列的默认/最小/最大宽度，以及排序、列显隐、列重排的交互位置。
3. 给出检查器折叠/展开时的布局（宽度阈值、动画、键盘快捷键）。
4. 给出工具栏默认项的图标、标签、辅助功能名称，并明确哪些项可自定义、哪些固定。
5. 给出状态徽章的完整状态矩阵：Completed → 正常/已加密/暂存/只读；Pending → 处理中/待保存；Cancelled → 错误/不支持。

### P2 — 中风险（优化视觉与辅助功能）

1. 移除固定亮绿，改用系统强调色，并给出增强对比度/降低透明度下的回退样式。
2. 为表格行增加斑马纹或悬停背景，确保选择/焦点状态清晰。
3. 为暗色模式补充对比度检查，确保所有文本 ≥ 4.5:1。
4. 为 2x 缩放和紧凑模式提供布局稿，确保“压缩后大小”等长中文列不被截断。
5. 将客户名绿色改为普通文本或链接色，避免与状态颜色混淆。

### P3 — 建议（提升工程效率）

1. 将视觉目标拆分为多个独立 PNG/线框：整体布局、列表视图、媒体预览、空状态、搜索状态、创建归档面板、解压缩面板、设置窗口。
2. 为每个组件标注对应 SwiftUI/AppKit 推荐实现方式（如 `NavigationSplitView` + `Table` + `Inspector`）。
3. 在视觉稿中标注 Liquid Glass 使用范围（标题栏、工具栏、侧边栏、检查器边缘、视图切换），并明确禁止区域（列表行、预览内容、filmstrip）。

### 视觉验收测试列表（最终进入实施前必须逐项通过）

- [ ] 列表视图：展开/折叠文件夹、排序列、调整列宽、选择行、键盘导航。
- [ ] 检查器：显示/隐藏、调整宽度、显示预览和元数据、不影响表格操作。
- [ ] 媒体预览：切换目录、底部 filmstrip、键盘切换媒体、视频不自动播放、不覆盖控件。
- [ ] 视图切换：列表/网格/媒体分段控件、手动选择后持久化、不自动跳回推荐模式。
- [ ] 暗色模式：系统外观切换、文本对比度、状态徽章可见、表格行区分。
- [ ] 降低透明度：不使用自定义玻璃、层级仍然清晰。
- [ ] 2x/紧凑模式：核心操作和列标题不被截断、侧边栏可收起。
- [ ] VoiceOver：导航顺序为窗口身份→工具栏→侧边栏→内容→检查器→状态栏。
- [ ] Quick Look：空格预览不覆盖表格、检查器预览与系统 Quick Look 一致。
- [ ] 状态语义：不只用颜色、状态图标/文字/徽章一致。
