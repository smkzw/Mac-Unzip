## 视觉结论

### 2.1 核心发现：视觉目标图像的“身份错配”
经过对 `adaptive-finder-media-visual-target.png` 的像素级视觉比对与内容审计，本模型指出一个**极其关键且具有阻断性（Blocking）的实施风险**：

> **当前提供的视觉目标图像实际上是 Web 端开源 AI 对话平台 LobeChat 的“工作区设置（Workspace - Common Setting）”截图，而非任何 macOS 原生的 Finder 风格或媒体预览界面。**

这一错配导致了设计规格（2026-07-11_full_design_spec.md）中宣称的“Finder-like 稳定外壳、媒体预览画布、底部胶卷带（filmstrip）”与当前视觉基准图存在完全的物理割裂。

### 2.2 视觉转化可行性评估
如果将此图像强行理解为“归档工作台设置面板”的视觉参考，其设计语言属于典型的 **Web/PWA (Progressive Web App) 风格**，具有极简、大间距、多色彩主题的特点。然而，若将其作为**整个应用主窗口（Finder 替代/融合外壳）的视觉基准，则是完全不可行的**。

我们必须在后续的“分级修改清单”中，将这些 Web 特征进行彻底的原生 macOS HIG（Human Interface Guidelines）重构，否则该产品在 Apple Silicon macOS 平台将失去其作为“原生应用”的商业说服力和操作熟悉感。

## 原生 macOS 与 Liquid Glass

将当前视觉目标（LobeChat 设置风格）与 macOS 原生体验进行对比，存在以下严重的“非原生”视觉违背：

### 3.1 窗口铬黄与控制区（Window Chrome & Traffic Lights）
* **严重违背**：图像中完全缺失 macOS 原生的“红黄绿”三色控制按钮（Traffic Lights）。
* **修正方向**：必须引入 macOS 标准标题栏。在 macOS Sequoia/Sonoma 中，应使用统一标题与工具栏结构（Unified Titlebar/Toolbar），将窗口控制按钮置于左上角，且支持系统级窗口拖拽。

### 3.2 侧边栏与导航模式（Sidebar & Navigation Rail）
* **严重违背**：
  1. **最左侧极窄图标轨（Far-left vertical navigation bar）**：这是典型的 Web/Slack 侧边栏，通过单图标纵向排列切换大板块。macOS 原生 Finder 绝不使用此类窄轨。
  2. **中间二级菜单栏（Middle Column Settings Menu）**：采用无图标纯文本列表。
* **修正方向**：应将这两栏合并为 macOS 标准的 `NSOutlineView` / SwiftUI `SidebarListStyle` 侧边栏。侧边栏应包含标准宽度（通常为 180~240pt）、原生模糊半透明（Vibrancy）效果，并支持标准的“最近使用”、“收藏位置”、“目录树”等可折叠折叠组（Disclosure Groups），使用标准尺寸的 **SF Symbols**，而非 Web 风格的极细线框图标。

### 3.3 表单与交互控件（Interactive Controls）
* **下拉选择器（Dropdowns）**：图像中的 FontSize 和 Language 选择器采用矩形细线边框、单向下箭头。这属于 Web 自定义 select。macOS 原生应使用带有上下双三角箭头的 `NSPopUpButton` 样式，或遵循 macOS Sequoia 带有内阴影与圆角的系统级 Picker 样式。
* **切换开关（Toggle Switch）**：Theme Mode 的开关为长椭圆、左右纯色分块、圆钮。这偏向 iOS/Web 风格。macOS 原生开关具有更紧凑的横纵比、浅色描边，且其蓝色填充在 macOS 上有特定的系统标准色。
* **分段控件（Segmented Control）**：Direction 的 LTR/RTL 切换采用硬边界、深蓝色高亮。macOS 标准的 `NSSegmentedControl` 应有金属凹陷或磨砂半透明质感，选中态是轻微下沉的灰色或系统强调色圆角矩形，绝非高饱和度的 Web 扁平色块。

### 3.4 Liquid Glass（流态玻璃）材质审计
* **严重违背**：图像中的背景为 100% 不透明的实色浅灰（#F3F3F3 左右），各面板为实色纯白，边框为 1px 的不透明灰色。**完全没有任何 Liquid Glass 或系统 Vibrancy（材质振动）效果。**
* **限制与应用建议**：根据 `SOUL.md` 和设计规格，Liquid Glass 只能应用于标题栏、侧边栏、检查器边缘。在实现时，必须采用 macOS 系统提供的 `NSVisualEffectView`（材质选用 `sidebar` 或 `window`，混合模式选用 `behind-window`），以实现真正随桌面背景实时变化的毛玻璃效果。绝对禁止在主内容列表区使用自定义 Web 模糊，这会导致性能严重下滑和渲染重影。

## 层级布局与交互风险

### 4.1 严重的 RTL 交互与视觉冲突（Direction RTL/LTR Bug）
* **漏洞描述**：图像最下方的一行中，"Direction" 控件被设置为了 **"RTL"（Right-to-Left，从右至左）**，但界面却依然呈现出 **"LTR" 布局**（即：标签在最左侧对齐，表单控件在最右侧对齐）。
* **交互风险**：在真正的 RTL 语言（如阿拉伯语、希伯来语）环境下，整个界面的视觉流向必须彻底水平翻转——侧边栏应移至右侧，文字标签右对齐，控件靠左。图像中的这种“标签在左、控件在右，却高亮 RTL”的排版是极不合逻辑的交互 Bug。

### 4.2 三栏布局的空间争夺（Navigation/Preview Balance）
* **布局矛盾**：如果强行套用图像中的布局：
  * 最左侧窄轨 + 中间二级导航栏占用了窗口近 **35%** 的水平宽度。
  * 仅剩 **65%** 的宽度供右侧主内容区使用。
* **媒体预览失效**：根据设计规格 4.3 节，“媒体预览视图”需要一个“大尺寸安全预览（中央）”和“底部胶卷带（filmstrip）”。在 65% 的残余宽度下，中央大预览区将被极度压缩，丧失其“高保真、直观评估”的价值。右侧一旦展开检查器，主预览区将被完全挤压至无法看清。

### 4.3 列表视图与预览视图的“无缝平滑切换”
* **跳变隐患**：图像中的 settings 表单是扁平行结构。如果用户点击“视图切换”，界面在 LobeChat 风格的扁平设置行与 Finder 风格的层级多列表格（Columns: 名称、大小、压缩大小等）之间切换，会导致：
  1. 侧边栏宽度、整体水平锚点剧烈跳变。
  2. 搜索框、主命令按钮位置发生瞬时位移。
* **解决方案**：外壳（Sidebar、Toolbar、Titlebar）必须 100% 独立于内容区。中间与右侧内容区采用标准的容器替换（Container Swapping），在切换视图时，仅刷新内容 Canvas，外壳结构和宽度保持绝对静止。

## 可访问性与中文显示

### 5.1 文本对比度与可读性风险（Contrast & Accessibility）
* **对比度过低**：图像中表单项下方的描述文字（如 "Switch between light and dark themes"）字重极轻（估计为 Light 300），颜色为中灰色，背景为纯白。
* **无障碍违背**：经估算，该灰色文本在白色背景上的对比度低于 **3.0:1**，严重违反了 WCAG 2.1 AA 级标准中“普通文本对比度至少达 4.5:1”的硬性要求。对于视力受损或使用低端显示器的用户，这些关键的交互说明几乎不可读。
* **系统自适应**：在 macOS 开启“增强对比度（Increase Contrast）”时，应用必须将此类描述文字强制提升为纯黑（#000000），并将所有面板分割线由 1px 细线改为高对比度实线。

### 5.2 简体中文优先的排版适配
* **文字膨胀与高度截断**：当前界面为全英文。当替换为规格书第 7 节定义的中文术语（如 "Theme Mode" -> "主题模式"，"Theme Color" -> "主题色"）时：
  * 英文单词较长，中文词组较短，这通常会导致左侧标签区域显得空旷。
  * 但在某些长描述语境下，中文字体（如 `PingFang SC`）在相同字号（如 12pt/13pt）下的高度和视觉占比大于英文字体。若行高（Line Height）或垂直 padding 依然沿用 Web 端的紧凑像素值，中文字符的顶部和底部可能会被控件边框或分割线“像素级裁切（Clipping）”。
* **系统字体平滑**：Web 渲染（如 Electron/Chromium）在 macOS 上的字体渲染机制（Antialiasing）与原生 AppKit/SwiftUI 存在微小色差。原生 SwiftUI 渲染的中文在大字号下更具边缘清晰度，而 Web 渲染在非 Retine 屏上容易出现发虚、彩边现象。

## 分级修改清单

为将当前的“LobeChat 伪视觉目标”改造成符合 2026-07-11 规格书标准的**原生 macOS 归档工作台外壳**，我们提供以下无代码、纯视觉与层级的分级修改清单：

### 3.1 P0：阻断性原生 macOS 违背项（优先度：最高，必须重构）
1. **重构窗口外壳**：
   * **位置**：窗口最顶层。
   * **修改**：废弃当前的纯 web 无铬设计。添加原生 macOS 标题栏，在左上角放置标准的红、黄、绿“交通灯”窗口控制按钮。
2. **废弃极窄导航轨，合并为标准侧边栏**：
   * **位置**：窗口左侧（原最左窄轨 + 中间 Workspace 二级栏）。
   * **修改**：将两栏合并为单一的标准 macOS 侧边栏（宽度 200pt，支持拖拽调整）。使用 `sidebar` 材质的 `NSVisualEffectView` 实现原生流态玻璃效果。
3. **侧边栏内容标准化**：
   * **位置**：新合并的左侧侧边栏。
   * **修改**：使用系统标准的 SF Symbols，设立“最近使用”、“收藏位置”等标准的 macOS 侧边栏折叠组。当前打开的“压缩包目录树”应作为侧边栏的最核心层级视图。
4. **替换非原生表单控件**：
   * **位置**：所有交互表单。
   * **修改**：
     * 下拉选择器（FontSize、Language）必须改用标准的 `NSPopUpButton` 样式，加入双三角箭头，边缘使用原生内阴影。
     * Toggles（Theme Mode）改用 macOS 系统级开关，横纵比缩小，对齐原生比例。
     * Segmented Control（Direction）改用磨砂 Recessed 样式的原生分段控件，取消饱和度过高的扁平色块高亮。

### 3.2 P1：交互与布局风险项（优先度：中，影响核心功能）
1. **纠正 RTL 视觉与排版 Bug**：
   * **位置**：Direction 表单行。
   * **修改**：如果选中 RTL，则整行布局必须镜像翻转。但在默认中文（LTR）环境下，应默认高亮并选择 "LTR"。
2. **重分配主内容区水平预算**：
   * **位置**：整个窗口比例。
   * **修改**：左侧侧边栏固定/自适应宽度（180pt~240pt），将余下的 **75%~80%** 宽度完整保留给中央内容区。右侧的“属性检查器（Inspector）”设计为可折叠式（类似 Finder 预览窗格或 Xcode 右侧栏），平时隐藏，点击工具栏 `⌥⌘I` 展开，不挤占中央大媒体预览空间。
3. **外壳与内容解耦，防止视图跳变**：
   * **位置**：工具栏与主内容容器。
   * **修改**：工具栏中的“列表/媒体预览”分段控件在切换时，窗口整体外壳（标题栏、侧边栏、工具栏、状态栏）保持静态不动，仅中央容器在“标准多列列表（NSTableView）”与“大图安全预览区 + 底部胶卷带（Filmstrip）”之间做平滑过渡，防止交互焦点丢失。

### 3.3 P2：视觉细节与可访问性提升项（优先度：低，打磨体验）
1. **提升文本对比度**：
   * **位置**：表单说明文字（如各项设置下方的 Description）。
   * **修改**：将灰色文本的字重提升为 Regular (400)，颜色加深，确保在纯白背景下的对比度至少达到 **4.5:1**。
2. **中文字体适配与防截断**：
   * **位置**：全界面文本标签。
   * **修改**：文字默认使用系统级字体（`.AppleSystemUIFont`），在中文环境下自动映射为 `PingFang SC`。增加行高预算 15%，确保中文字符的上下边缘留有足够的像素安全间距，杜绝像素裁切。
3. **专业词汇本地化替换**：
   * **位置**：视图切换标签。
   * **修改**：工具栏切换控件中的 “LTR / RTL” 对于普通归档用户过于晦涩，应在中文环境下翻译为“左至右 (LTR)”和“右至左 (RTL)”，或使用象征排版流向的辅助图标。
