> 密码以可控的字节缓冲传递，避免长期 Swift `String` 副本；C 适配器只在最短作用域创建本地缓冲，使用后显式清零。对 7zz/RARLAB，固定版本 provider 仅可使用工具自身的交互式密码模式：启动参数只含不带密码值的提示开关，helper 通过该子进程独占、不可继承的 stdin/伪终端写入一次密码字节并立即清零；禁止 argv、环境变量、普通/临时文件、剪贴板和 shell。若经 Xcode spike 证明某个固定版本无法在该合同下可靠工作，则该版本的加密操作保持禁用，不退回泄漏机制。不承诺对已被系统/框架复制的内存绝对擦除，但 crash/诊断收集必须排除密码字段。

## 2. 攻击尝试

针对当前 §18 定义的合同，逐项验证是否存在残余攻击面：

### 2.1 stdin fd 被子进程继承

**攻击**：helper fork/exec 7zz 时，若 stdin fd 未设 `FD_CLOEXEC`，7zz 自身可能 spawn 的子进程会继承该 fd。

**当前防御**："独占、不可继承的 stdin" — "不可继承" 即 POSIX `O_CLOEXEC` 语义。helper 必须在创建 pipe/pty 后、exec 前设置 close-on-exec。

**结论**：合同已覆盖。实现必须执行 `fcntl(fd, F_SETFD, FD_CLOEXEC)` 或等效操作，但合同层面已明确要求"不可继承"。

### 2.2 pty 被其他进程读取

**攻击**：伪终端从设备（slave）的文件节点权限允许同用户其他进程打开并读取。

**当前防御**：pty 通过 `posix_openpt()`/`grantpt()`/`unlockpt()` 创建时，slave 节点权限由系统管理（通常 `0620`，owner=tty 组）。helper 持有 master fd，子进程持有 slave fd。合同要求"独占"，隐含 helper 不得将 master fd 传递给其他进程。

**结论**：合同层面的"独占"约束已足够。具体 pty 权限管理属实现细节。

### 2.3 7zz 内部将密码写入临时文件

**攻击**：某些 7zz 版本在 stdin 读取密码后可能内部缓存到临时文件。

**当前防御**：安全禁用路径明确覆盖——"若经 Xcode spike 证明某个固定版本无法在该合同下可靠工作，则该版本的加密操作保持禁用，不退回泄漏机制"。若 spike 发现此行为，加密禁用。

**结论**：已被安全禁用路径覆盖。Xcode spike 需将此作为验证项之一（属实施范畴）。

### 2.4 helper crash 时密码残留在 core dump

**攻击**：helper 进程崩溃时，内存中的密码字节可能写入 core dump。

**当前防御**："crash/诊断收集必须排除密码字段"。实现层面需要：禁用 helper core dump 或确保 crash 收集器过滤密码页；合同层面已要求排除。

**结论**：合同已覆盖。

### 2.5 环境变量通过 `/proc` 泄漏

**攻击**：即使不显式设置密码环境变量，`7zz` 可能从继承的环境中读取。

**当前防御**：§16 规定 helper 环境为"最小环境"，§18 明确禁止环境变量传递密码。合一——helper 不设任何密码相关环境变量，7zz 无 env 可读。密码仅经 stdin/pty。

**结论**：合同层面已闭合。
