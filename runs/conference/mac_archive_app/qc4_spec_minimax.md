## 4. 视觉方向决策与规格的一致性

视觉决策 § `Decision` 指定方向 1+3 组合,带"方向 1 必须进一步朝原生 Finder 信息层级与交互行为靠拢"的要求。规格落实:

- §4.2 列表视图使用 Finder 原生层级表格 + 五列默认列(名称/大小/压缩后大小/类型/修改日期)
- §4.3 媒体预览保留左侧归档目录树、中央大预览、底部条带(无可见标题)、右侧检查器
- §5.2 已打开压缩包窗口三栏布局(标题/侧边栏/中央/检查器/底部状态)
- §4.4 仅两个系统图标视图切换按钮
- §4.5 Liquid Glass 使用范围约束(允许/禁止分明)+ 降低透明度/增强对比度/减少动态效果回退

视觉决策 QC-3 修正段六条要求(`one archive sidebar only` / `main area is either the hierarchical list or media preview` / `inspector is optional and collapses first at narrow widths` / `no 更多文件…, sidebar +/-, or visible filmstrip heading` / `no duplicate extract action and no always-visible 创建归档 inside an open document` / `operation history is a toolbar popover/independent window, not a date tree in navigation` / `archive and child counts must reconcile in the fixture`)的逐条对应:

- 单一归档侧边栏 → §5.2 第 118 行(已检)
- 主区域仅承载列表/媒体预览 → §5.2 第 118 行 `主内容区始终只承载列表、搜索结果或媒体预览` + §4.4
- 检查器先收起 → §5.1 第 112 行 `低于能同时容纳三栏的宽度时,检查器先收起为工具栏入口`
- 无 `更多文件…`/侧边栏 `+/-`/条带标题 → 规格未使用这些命名(检查通过:全文搜索"更多文件"和"+/−"无用户可见 UI 命名命中)
- 无重复解压动作 + 文档窗口内不总是显示 `创建归档` → §6.1 默认工具栏无 `创建归档`(`⇧⌘N` 仍可,§6.2 `文件` 菜单有 `创建归档`,符合 macOS 文档窗口惯例);§5.2 已打开压缩包窗口未列 `创建归档`
- 操作历史非导航侧栏 → §21(已检)
- 夹具中父子计数一致 → 实施期夹具约束,不属规格阶段

判定: 视觉决策与 0.10 规格的对应完整、无新增矛盾。

## 6. 残留 P2 实施期细化(非阻断)

下列项已识别但**不构成 P0/P1 矛盾**,可在实施计划阶段统一处理:

1. **§10 第 292 行 `全部名称转换为 UTF-8 后另存为` 的 UI 形态**:规格指定"保存前明确提示并允许改为...另存为",但 UI 形态(对话框 / Sheet / 内联提示条)未硬性规定。建议实施期采用 SwiftUI native confirmationDialog 形态,在编码与格式选项组合触发时弹出。
2. **"提取"复合名词统一**:§2.1 §14.6 §17 §19 中"提取"均位于复合结构中,可统一在 String Catalog 中以 `提取` 作为动作动词保留,与主命令 `解压缩` 区分为名词 vs 动作。
3. **§5.2.1 搜索结果跨目录的 `路径` 列宽度策略**:规格强制显示 `路径` 列,但未规定过长路径的截断/省略策略;macOS Finder 默认中间省略,可沿用。
4. **§4.3 媒体建议阈值(70%/至少 4 项)的回退路径**:当用户拒绝建议后,如何在该目录二次进入(切换压缩包或重启后是否重置)未细化;§4.3 第 84 行说"按压缩包/目录在本地记忆",已隐含"重置条件=用户主动切回",但实施期需要明确状态存储结构。
5. **§30 门槛中"完整 Xcode 已安装或用户同意执行安装步骤"**:本规格审查范围内,Full Xcode 安装属于任务环境层面,不在规格阻塞路径上,但实施前必须解决。
6. **§29 验收场景 15 与 §24 100% 指标的关系**:§29 场景 15 要求 VoiceOver/键盘达成 §24 的 100% 指标,具体验证手段(XCUITestAccessibilityAudit + 人工 VoiceOver 录屏)在 §24 末尾已明确,自洽。

这些细化不属于"修订规格 vs QC-3 阻断项"的层面,仅是进入实施计划后需要的设计到工程映射细节。

## 7. 最终判定

**GO — 0.10 修订规格通过 QC-4,可进入实施计划阶段。**

理由:
1. QC-3 列出的全部 16 项阻断项在 0.10 中均有可定位、可验证的强约束修订,无新增 P0/P1。
2. 视觉方向决策 + 规格 + 追溯矩阵三份文件交叉对照,无矛盾或悬空需求。
3. 中文术语主体一致,§7 表格基线被严格遵守;"提取"的复合名词用法属 P2 细化。
