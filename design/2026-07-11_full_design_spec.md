# 归档工作台 macOS 应用全量设计规格

版本：0.10（QC-3 阻断项修订版）  
日期：2026-07-11  
状态：方案 A 与视觉方向已获用户批准；用户授权后续不再逐阶段审批，本规格通过 QC-3/Codex 门禁后自动进入实施计划  
产品工作名：`归档工作台`（名称仍可调整，不影响架构）

## 1. 产品目标

构建一款仅支持 Apple Silicon、面向最新 macOS 的原生压缩包浏览、预览、创建、解压缩和内容编辑应用。它的前后端能力、稳定性、安全性、性能、视觉和完整工作流以成熟商业产品为标准，但当前主要供用户本机安装使用。

应用同时保持两种未来交付能力：

- `Direct`：用户明确下令后，可构建 Developer ID 签名、公证并由网站直接分发的版本。
- `OpenSource`：用户明确下令后，可生成适合 GitHub 开源的版本与合规材料。

在用户明确下令前，不创建远程仓库、不上传 GitHub、不部署网站、不公开发布任何安装包。

## 2. 已批准的产品边界

### 2.1 包含

- ZIP、7z 的创建、浏览、搜索、预览、选择性解压、内容增删改、加密、分卷、完整性检测。
- TAR、GZIP、BZIP2、XZ、Zstandard 的创建、浏览和解压缩。
- RAR 的浏览、预览和解压缩；在本机存在合法授权并通过探测的 RARLAB `rar` 时启用创建/更新。
- DMG、ISO 的只读浏览/提取；DMG 可按安全规则只读挂载。
- Mac 与 Windows 接收方兼容预设。
- 简体中文优先，繁体中文与英文完整；文件名兼容更多语言和旧代码页。
- Finder 风格的原生窗口、Quick Look、Finder 快速操作、拖放、菜单、快捷键、VoiceOver。
- Local、Direct、OpenSource 三个构建配置。

### 2.2 不包含

- Intel/x86_64 支持。
- Mac App Store 版本。
- iOS、iPadOS、云同步、压缩包托管或协作服务。
- 未经授权的 RAR 编码器或捆绑 RARLAB 二进制文件。
- 不可恢复的直接原地改写。
- 自动执行压缩包内程序、脚本、宏或挂载内容。

## 3. 设计原则

1. **内容优先**：文件列表和预览是主角；Liquid Glass 只承担导航、工具和上下文层级。
2. **Finder 熟悉感**：窗口、侧边栏、选择、排序、列、拖放、快捷键和 Quick Look 遵循 macOS 习惯。
3. **先说明代价再执行**：完整重建、弱加密、第三方接收工具、路径重命名和元数据损失都在操作前可见。
4. **源文件优先保全**：取消、崩溃、磁盘不足、外部修改或引擎失败不得损坏唯一源压缩包。
5. **能力真实可见**：界面从运行时能力注册表读取支持状态，不从扩展名猜测，也不显示不能工作的按钮。
6. **接收方语言**：不向普通用户展示 W0/W1/W2；直接说明 Windows 是否可原生打开、是否需要 7-Zip/WinRAR。
7. **不静默修复**：编码、文件名、路径冲突、覆盖、损坏和引擎回退均需明确说明并可追踪。

## 4. 视觉基准与自适应视图

视觉基准文件：`design/assets/adaptive-finder-media-visual-target-v3.png`（v1/v2 仅保留为 QC 演进证据，不再作为实现目标）

### 4.1 稳定外壳

所有视图共享同一个窗口和选择状态：

- macOS 原生标题栏与可自定义工具栏。
- 左侧 Finder 式侧边栏；中间压缩包内容；右侧可折叠检查器。
- 返回/前进、路径上下文、搜索、视图切换和主要操作位置稳定。
- 路径栏使用可交互面包屑；每一级可跳转，也只在目标能力允许时作为安全拖放目标。
- 切换视图不得丢失选择、滚动位置、编辑暂存状态或搜索条件。

### 4.2 列表视图

普通文档、代码或混合内容的默认视图。

- 层级表格支持展开/折叠文件夹。
- 默认列：`名称`、`大小`、`压缩后大小`、`类型`、`修改日期`。
- 用户可以调整列宽、排序、显示/隐藏列；配置按本地视图状态保存。
- 右侧显示 Quick Look 预览和条目信息，可调整宽度或隐藏。
- 大压缩包使用增量索引、虚拟化列表和后台元数据加载。

### 4.3 媒体预览视图

当前目录的非文件夹行中，可安全预览的图片/视频至少 4 项且占比至少 70% 时，内容区顶部显示一次非模态提示`建议使用媒体预览`；应用不自动切换。这是待实测调优的初始阈值。

- 左侧仍保留压缩包目录树。
- 中央显示大尺寸安全预览。
- 底部显示当前目录的全部媒体项目条带，支持键盘、触控板、滚轮与多选；搜索结果跨目录时不显示条带，改用带`路径`列的扁平结果。
- 右侧检查器显示类型、大小、压缩后大小、修改日期、路径等。
- 视频不自动带声音播放；使用系统播放控件。
- 用户手动选定视图后，不再自动切换；选择按压缩包/目录在本地记忆，不写入压缩包。

### 4.4 视图切换

v1 工具栏采用两个系统图标按钮切换列表与媒体预览；不显示尚未实现的图标/网格视图。控件有中文辅助功能标签：

- `列表视图`
- `媒体预览`

### 4.5 Liquid Glass 使用范围

允许：标题栏、工具栏、侧边栏、检查器边缘、视图切换、紧凑进度/上下文控件。  
禁止：每个文件行套玻璃卡片、玻璃覆盖预览内容、装饰性重叠玻璃、影响文本对比度的自定义模糊。

在“降低透明度”“增强对比度”“减少动态效果”开启时，使用系统回退表现，不手工模仿玻璃。若目标 SDK 的 Liquid Glass API 不可用或行为变化，则退化为标准 macOS toolbar/sidebar/inspector 系统材质；功能层级、间距、对比度和可访问性语义不得变化，不自行用自定义模糊复刻。

## 5. 窗口与信息架构

### 5.1 无文档窗口

首次打开或没有窗口时显示简洁欢迎页：

- 主操作：`打开压缩包…`
- 次操作：`创建归档…`
- 最近使用列表。
- 可将文件/文件夹拖入窗口；拖入压缩包则打开，拖入普通项目则进入创建流程。
- 不显示功能清单、营销卡片或空洞指标。

默认文档窗口 1180 × 760 pt，最小 900 × 560 pt；低于能同时容纳三栏的宽度时，检查器先收起为工具栏入口，侧边栏再改为可呼出覆盖层，主文件列表不得被压到不可操作。

顶部工具栏在默认宽度、最小宽度与放大窗口下不得发生按钮、标题、搜索框或系统交通灯重叠；固定阅读顺序为`压缩包标题 → 返回/前进 → 添加/解压缩 → 视图/信息 → 操作 → 搜索`。标题使用标题栏安全边距内的普通单行布局，不用可能越过窗口边缘的独立胶囊容器；默认宽度下两个主操作必须显示完整中文名称。`检测完整性`不是高频一级操作，与`共享`、`标签`、`当前操作`等次要项一起进入有明确中文名称的`操作`菜单；仅在损坏、下载不完整或分卷异常等情形通过状态提示推荐检测。空间不足时再按`检查器收起 → 侧边栏覆盖`响应；不显示含义模糊的独立省略号`更多`按钮，也不得让系统把关键分组重排到搜索框之后。压缩包标题与条目文件名均保持单行；长名称采用中间省略以优先保留扩展名，完整名称通过悬停提示、辅助功能标签和信息栏提供，不允许自动换行破坏行高或缩略图条带节奏。媒体条带的圆角底和选中描边只包围缩略图；文件名与大小在其下方的透明背景上独立排版，不增加圆角文字容器，也不得与缩略图边框相交。

### 5.2 已打开压缩包窗口

- 标题：压缩包文件名。
- 副信息：格式、加密状态、项目数量、只读/可编辑状态。
- 左侧使用单一归档侧边栏：`压缩包`目录树为主体，可折叠显示`收藏位置`；不得同时并排出现一套 Finder 位置侧栏和第二套归档目录栏。操作记录不占用导航侧栏。主内容区始终只承载列表、搜索结果或媒体预览。
- 中央：列表/媒体预览。
- 右侧：`信息`/`预览`检查器。
- 底部状态：选择数量、总大小、完整性或暂存编辑状态。

### 5.2.1 搜索结果

搜索不改变压缩包层级数据。结果使用扁平列表，强制显示`路径`列，并保留类型、大小、修改日期和父目录跳转。清除搜索后恢复原目录、选择和滚动状态。搜索结果可预览、解压缩或定位到原位置；批量编辑前再次做全树冲突检查。

### 5.2.2 常用位置

应用本地维护`收藏位置`与最近使用的解压目标。创建/解压预设可以引用这些位置，但始终显示实际目标。移除收藏不删除磁盘内容。安全作用域书签失效时显示重新授权，不静默改用其他位置。

### 5.3 创建归档面板

主要区域依次为：

1. 待归档项目列表。
2. `用途`预设：`发给 Windows 用户`、`跨平台加密分享`、`兼容旧版解压软件`、`长期归档`、`自定义`。
3. `格式`、`压缩方式`、`压缩级别`、`加密`、`分卷大小`。
4. 文件名与 Windows 兼容预检结果。
5. 保存位置与文件名。
6. 主按钮：`创建归档`。

高级选项始终显示真实格式与接收方要求；预设不隐藏关键事实。

### 5.4 解压缩面板

- 目标位置。
- 范围：全部或所选项目。
- 冲突策略：`逐项询问`、`保留两个文件`、`跳过`、`替换`；默认逐项询问；逐项面板提供`对其余冲突应用此决定`。
- 安全摘要：预计项目数/大小、异常路径、符号链接、资源风险。
- `解压缩后在 Finder 中显示`开关；仅定位并选中结果，不直接打开任何文件。
- 主按钮：`解压缩`。

常用/最近目标以菜单形式提供，不挤占主面板。任何预设都不能包含解压后自动运行脚本或程序。

### 5.5 设置窗口

原生 macOS `Settings` 场景，v1 使用六个一级分类并定义默认值：

- `通用`：启动时显示欢迎页（开）；恢复上次未关闭窗口（开）；最近使用数量（10）。
- `解压缩`：默认目标（每次询问）；冲突策略（逐项询问）；完成后在 Finder 中显示（关）；保留 quarantine（开）。
- `创建归档`：默认用途（发给 Windows 用户）；默认排除 macOS 元数据（开且适用于所有创建格式）；保存前自动检测完整性（开）。
- `兼容性`：旧文件名编码（自动检测）；可按当前压缩包临时选择代码页；Windows 路径预检（开）。自动检测顺序为格式明确标志/BOM、严格 UTF-8、受支持代码页启发式；置信度不足时必须询问，不静默猜测。
- `密码与外部工具`：钥匙串保存策略（默认不保存）；管理已保存密码；选择并验证 RARLAB `rar`；显示 7zz 版本与许可证。
- `隐私与高级`：诊断路径脱敏（始终开）；预览缓存上限（默认 1 GiB）；并发外部任务（默认 2、范围 1–2）；重置视图状态。安全硬限制不可在此关闭。

## 6. 工具栏、菜单与快捷键

### 6.1 默认工具栏

- `打开` — `⌘O`
- `创建归档` — `⇧⌘N`
- `添加` — `⌥⌘A`（可编辑压缩包）
- `移除` — `⌫`（有选择且可编辑）
- `重命名` — `Return`
- `解压缩` — `⌘E`
- 视图切换
- `信息` — `⌥⌘I`
- `操作`菜单 — 检测完整性、共享、标签、当前操作等低频项
- 搜索 — `⌘F`

`保存`使用 `⌘S`；`另存为…`使用 `⇧⌘S`。Space 打开/关闭预览；`⌘1`为列表视图，`⌘2`为媒体预览，`⌘,`打开设置，`⌘?`打开帮助。Return 第一次进入重命名编辑，第二次确认，Escape 取消。所有快捷键需检查与系统菜单冲突，并在实现阶段用真实菜单验证。

有次要选项的工具栏操作使用清晰的相邻菜单箭头或独立菜单，不依赖用户发现“长按按钮”。

工具栏响应式验收至少覆盖 900 pt、1180 pt 与最大化宽度；自动化检查可见控件框不相交，长中文、拉丁字母、组合字符与长扩展名夹具不换行，且完整文件名仍可由 VoiceOver/帮助文本取得。

### 6.2 主菜单

- `文件`：打开、最近使用、关闭、创建归档、保存、另存为、解压缩、完整性检测。v1 不显示尚未完整设计和实现的转换入口。
- `编辑`：撤销/重做、剪切/复制名称、全选、添加、移除、重命名、替换。
- `显示`：列表/媒体预览、显示/隐藏侧边栏、检查器、预览、列设置、排序。
- `归档`：添加、移除、重命名、加密设置、分卷、检测完整性、修复（可用时）。
- `窗口`与`帮助`遵循系统默认结构。

## 7. 中文术语基线

| 概念 | 界面用语 | 使用说明 |
|---|---|---|
| archive noun | `压缩包`（面向用户）/`归档`（系统命令和格式语境） | 避免机械统一；上下文一致 |
| create archive | `创建归档` | 对齐当前 macOS |
| extract | `解压缩` | 主命令；不用`展开`或孤立的`提取` |
| open | `打开` | 打开压缩包或预览 |
| add entry | `添加` | 添加到当前压缩包 |
| remove entry | `移除` | 未保存前可撤销；不用`删除文件`误导源文件 |
| rename entry | `重命名` | 暂存更改 |
| replace entry | `替换内容` | 明确不是同名覆盖整个压缩包 |
| save | `保存更改`/菜单`保存` | 7z 等需显示重新生成代价 |
| save as | `另存为…` | 分卷编辑或只读位置 |
| test | `检测完整性` | 不使用模糊的`测试压缩包` |
| repair | `尝试修复副本…` | 永不覆盖唯一源文件 |
| split archive | `分卷压缩包`/`分卷大小` | 缺卷用`缺少分卷文件` |
| encrypted | `已加密` | 与“需要密码”“不支持的加密方式”分开 |
| settings | `设置…` | 不用旧称`偏好设置` |
| keychain | `钥匙串` | 对齐 macOS |
| queue/history | `当前操作`/`近期操作`/`操作历史` | 按时间尺度区分，不把运行任务与历史混在一起 |
| Windows native | `Windows 11 可直接打开` | 不显示 W0 |
| third-party required | `接收方需要 7-Zip 或 WinRAR` | 不显示 W1 |

最终字符串必须进入 String Catalog，带使用场景、语法和辅助功能注释；不能散落硬编码。

## 8. 格式与能力注册表

`ArchiveCapabilityRegistry` 是唯一真相来源。能力键至少包含：

- 格式与实际探测结果。
- 操作：列出、读取、预览、创建、更新、加密、分卷、检测、修复。
- 加密/压缩方法。
- 主引擎、只读诊断回退。
- 是否需要完整重建。
- 是否需要外部工具及其验证状态。
- 当前构建配置可用性。
- 用户可读的不可用原因。

确定性路由：

- ZIP：minizip-ng。
- 7z：`7zz`。
- TAR/CPIO 与 GZIP/BZIP2/XZ/Zstandard：libarchive。
- RAR 读取：`7zz`，libarchive 仅作支持范围内的只读诊断。
- RAR 创建：外部 RARLAB `rar`。
- ISO：libarchive。
- DMG：macOS 磁盘映像流程。

任何编辑事务开始后不得切换引擎。回退只能在打开/诊断阶段发生，并向用户说明原因。

ZIP 中出现 minizip-ng 不支持的条目级压缩/加密方法时，仍由 minizip-ng 保持文档所有权：可安全列举的其他条目继续浏览，该条目标为`压缩方式暂不支持`并禁用预览/解压/替换；不得把同一编辑事务暗中切换给 `7zz`。用户主动执行`用诊断引擎检查`时，`7zz` 只返回独立诊断，不改变文档能力快照或保存引擎。RAR 的 libarchive 回退同样只用于诊断；即使诊断引擎声称可读，也不自动用它发布解压结果。

## 9. 领域模型

### 9.1 ArchiveDocument

- 源 URL/安全作用域书签。
- 格式探测与能力快照。
- 源文件身份、元数据和 SHA-256。
- 条目索引。
- 当前目录/选择/视图状态。
- 暂存更改集。
- 活动操作与恢复状态。

### 9.2 ArchiveEntry

- 稳定会话内 ID。
- 原始路径字节与解码显示名分离。
- 规范化比较键，仅用于冲突检测。
- 类型、压缩/原始大小、CRC/摘要（若有）、时间、权限、链接信息、加密状态。
- 预览支持与安全分类。

### 9.3 PendingChange

- `add`、`remove`、`rename`、`replace`、`metadataPolicyChange`。
- 原条目 ID、来源 URL、目标路径。
- 冲突/编码/兼容性检查结果。
- 用户可撤销顺序。

### 9.4 ArchiveOperation

- 操作 ID、类型、阶段、进度、可取消性。
- 引擎/提供方与版本。
- 输入/输出、结构化警告与错误。
- 已脱敏的诊断信息。

操作对象可序列化到本地操作记录，但不能转换成可执行 shell 字符串。调度器支持顺序任务、每压缩包修改互斥、最多两个外部任务及系统资源感知；操作记录保存引擎/版本/提供方身份以便复现。

## 10. 打开、索引和浏览流程

1. 用户选择或拖入文件。
2. 读取签名并探测格式；扩展名仅作提示。
3. 能力注册表选择唯一主读取器。
4. 需要密码时显示安全输入，不把“密码错误”“没有提供密码”“不支持加密”混为一谈。
5. 增量读取目录并先显示可用内容；后台完成索引、摘要和安全扫描。
6. 格式探测、索引和 SHA-256 使用同一个已打开文件描述符；保存打开快照。哈希完成前可以只读浏览，但不得开始保存事务。
7. 恢复该压缩包本地视图状态。
8. 若当前目录满足媒体建议规则且用户从未手动选择视图，可建议媒体预览；不强制跳变。

启动时收到压缩包文件参数时直接将其作为初始文档打开。旧编码压缩包的原始路径字节始终保留；用户覆盖编码只改变显示/导出解释，不改源。编辑旧编码 ZIP 后保存时，未改变的原条目保留原始名称字段；新增或改名条目写入 UTF-8 并设置 bit 11。若结果产生混合编码，保存前明确提示并允许改为`全部名称转换为 UTF-8`后另存为，绝不静默重编码。

打开失败分类：格式不支持、文件损坏、目录损坏、密码缺失、密码错误、加密不支持、缺少分卷、提供方不可用、权限不足、资源限制。

## 11. 预览流程

1. 选择条目后先判断类型、大小、加密与安全分类。
2. 每个窗口创建随机 `0700` 缓存根目录。
3. 条目 ID 映射为随机磁盘名，仅保留验证后的显示扩展名；压缩包路径绝不直接成为缓存路径。
4. 使用排他/不跟随链接方式创建并执行规范化包含检查。
5. 受每文件 256 MiB、每窗口 1 GiB、30 秒约束；单条目预计解压比例超过 50:1 时不生成预览，显示`此项目的压缩比例异常，请解压缩后查看`。该预览比例限制不可覆盖；如无法可靠获得压缩后/展开大小，也不在预览路径中试探性展开。
6. 添加 quarantine；特殊文件和链接不进入预览。
7. 预览是明确的格式能力，不以“系统也许能打开”代替产品承诺：图片使用原生图像视图；PDF 使用 PDFKit；Word（`.doc`/`.docx`）、Excel（`.xls`/`.xlsx`）和 PowerPoint（`.ppt`/`.pptx`）使用系统 Quick Look 只读预览；视频使用原生播放器且不自动带声音播放；纯文本使用受限文本查看器。Office/Quick Look 输入必须是通过本节安全流程产生的随机缓存文件，不得把压缩包路径或未校验输出直接交给预览器。
8. Quick Look 对受支持 Office 文档返回失败、超时或空预览时，界面显示明确的`无法生成预览`及`解压缩后打开`操作，不伪装为成功；这不降低“正常有效的 Word/Excel/PPT 必须可预览”的验收要求。实现必须使用真实 `.doc/.docx/.xls/.xlsx/.ppt/.pptx` 夹具逐类验证，并记录 macOS/Quick Look 版本。
9. 窗口关闭时删除缓存；启动时清理过期缓存。

所有预览缓存位于固定应用缓存根下的随机窗口 UUID 子目录。启动时在没有任何窗口活跃的阶段删除所有遗留窗口子目录，不依赖条目映射表或压缩包路径判断“过期”；清理失败记录诊断并在下一次启动重试。

内嵌压缩包不会自动递归。用户双击或从上下文菜单选择`在归档工作台中打开`时，才创建隔离子会话。整个会话链共享最多 3 层、10,000 项、1 GiB 展开字节和 60 秒预算；任一预算耗尽即停止，不允许覆盖。

## 12. 解压缩流程与冲突处理

1. 先建立完整目标计划，不边发现边无提示写入。
2. 拒绝绝对路径、`..`、空组件、NUL、越界路径和目标根外的规范化结果。
3. 符号链接、硬链接与特殊文件按安全策略分类；默认不允许链接逃逸。
4. 估计条目数、展开大小、压缩比、路径深度和可用空间。
5. 超过默认安全预算时阻止并解释；路径结构、链接逃逸和无法可靠列举的输入不可覆盖。预计总体或任一条目解压比例超过 100:1 时先阻止，用户仅可在重新确认目标空间、展开大小和风险后对显式解压缩单次覆盖；预览不可覆盖。
6. 名称冲突表一次性列出，也支持逐项决定；不能静默覆盖。
7. 以临时名称写入、验证后发布；部分失败有清晰结果清单。
8. 可选显示目标目录；不自动运行任何内容。

默认阻断阈值假设：预计输出超过 50 GiB 与目标可用空间 80% 中较小者、超过 1,000,000 项、路径深度超过 128、总体或任一条目解压比例超过 100:1。实施基准可以收紧非结构性阈值，不得在无安全评审时放宽。

### 12.1 外部引擎安全契约

`7zz` 的人类可读 stdout/stderr 只用于诊断，绝不作为路径安全、成功或完整性的唯一数据源。能由 minizip-ng/libarchive 的结构化 API 安全列举的格式先用结构化元数据建立目标计划。必须由 `7zz` 处理的加密/特殊 7z 或 RAR 始终先解到仅该任务可访问的随机暂存根；helper 不获得最终目标写权限。应用随后以文件描述符为根、不跟随链接地枚举实际产物，逐项执行包含性、类型、条目数、字节数和比例检查，全部通过后才发布到用户目标。任何无法结构化预检、越界产物、控制字符、未知节点类型、输出截断、版本协议不匹配或预算超限均整单失败并清理暂存，不尝试从文本行“修复”路径。

## 13. 创建归档流程

### 13.1 Windows 原生预设

`发给 Windows 用户`：

- 未加密 ZIP。
- Store/Deflate。
- UTF-8，local/central header 均设置 bit 11，无 BOM，不额外写冗余 Unicode Path 字段。
- 默认排除 `.DS_Store`、`._*`、`__MACOSX` 和非必要 macOS 元数据。
- 对 NFC、大小写、Windows 保留名、非法字符、尾随空格/点和路径预算做全树预检。

### 13.2 加密预设

- `跨平台加密分享`：7z AES-256 且加密文件名，显示`接收方需要 7-Zip 或 WinRAR`。
- `兼容旧版解压软件`：ZipCrypto ZIP，显示`兼容性较高，但密码保护较弱`。
- AES ZIP 显示第三方工具要求，不声称 Windows Explorer 可直接打开。
- 任何创建格式默认排除 `.DS_Store`、`._*`、`__MACOSX`；用户可在自定义选项中显式保留，但 Windows 预设不可保留。
- `发给 Windows 用户`与分卷同时启用时撤销`Windows 11 可直接打开`标记，并显示`Windows 资源管理器无法直接打开分卷压缩包；接收方需要 7-Zip 或 WinRAR`。

### 13.3 文件名冲突表

列：`原名称`、`输出名称`、`原因`、`接收方影响`。操作：逐项改名、应用可预览的批量规则、移除项目、切换保留原名的专业模式。每次改变后重新做全树冲突检测。

### 13.4 创建完成

创建成功不只看进程退出码：重新打开、检测完整性、核对条目清单；失败保留诊断并清理/记录暂存文件。

## 14. 编辑与保存事务

### 14.1 暂存编辑

添加、移除、重命名和替换首先进入本地 `PendingChange`，底部显示`N 项更改尚未保存`。用户可以逐项或全部撤销。

### 14.2 单文件压缩包保存

1. 检查目标目录可写和空间（空间仅作预估）。
2. 在目标同目录创建 `.ArchiveApp.<UUID>.staging`。
3. 使用固定主引擎生成完整结果。
4. 核对条目清单、摘要和引擎完整性结果。
5. fsync 暂存文件和父目录。
6. 通过 `NSFileCoordinator` 将源复核和替换纳入同一个协调写入块；块内重新检查设备/文件身份/大小/纳秒时间戳和 SHA-256。
7. 若源已变化，中止并提示`原压缩包已被其他应用更改`。
8. 在同一协调块内原子替换，释放协调后再次验证。

### 14.3 只读位置

源目录不可写时禁用原地`保存`，提供`另存为…`，并在用户选择的新目标旁暂存。

### 14.4 分卷压缩包

文件集不能原子替换。创建时在同级事务目录生成/验证完整分卷后，以新基名发布。编辑已有分卷始终使用`另存为…`，不提供虚假原地保存。

### 14.5 重建成本

7z 或其他需完整重建的操作在执行前显示预计读取/写入量与`保存时将重新生成此压缩包`，提供可取消进度；solid 7z 明确提示可能需要读取和重写整个 solid 块。取消、provider 失败、校验失败或崩溃后的重建暂存一律视为不可发布；可安全识别时自动删除，删除失败则进入恢复记录供用户显示/清理，绝不改变源或把部分结果改名为正式压缩包。

### 14.6 外部应用编辑回写

用户选择`用外部应用编辑副本`时：

1. 把条目提取到本窗口独立、受控、带 quarantine 的编辑目录。
2. 记录初始文件身份和 SHA-256。
3. 由系统打开副本；应用监视已保存变化，不监视任意外部目录。
4. 检测到变化后显示原/新大小、修改时间和可预览比较，询问`替换压缩包中的内容`或`忽略更改`。
5. 用户接受时重新读取并把当前内容快照复制到事务暂存区，计算 SHA-256 后与 `replace` 更改绑定；之后外部编辑器再次保存会产生新的变化提示，不会悄悄改变已暂存版本。仍需用户保存压缩包。
6. 关闭窗口时未处理变化必须提示；不自动回写。

### 14.7 修复副本

v1 的`尝试修复副本…`只对 ZIP 出现，将可恢复条目写入新文件，例如`原名称（已修复）.zip`，显示“无法保证恢复全部内容”，并在完成后重新检测。RAR/7z 等格式在能力、许可证和真实损坏夹具未独立验证前不显示修复按钮。修复永不覆盖源。

## 15. 崩溃恢复

- 恢复日志存于应用支持目录，只记录安全作用域书签、源指纹、暂存身份、操作和阶段，不记录密码；每条记录使用钥匙串内随机本机密钥做 HMAC，验证失败即隔离并记录诊断，绝不恢复或提交。
- 启动时扫描未完成事务；永不自动提交。
- 源和暂存均重新验证后提供`继续恢复`、`显示临时文件`、`删除临时文件`。
- 源已变化或暂存损坏时只允许保留/删除，不允许覆盖源。
- 磁盘不足、强制终止和每个事务阶段均需故障注入测试。
- 已完成/废弃恢复记录保留 30 天或合计 50 MiB（先到者清理）；正在恢复的事务不按时限自动删除。

## 16. 外部提供方与进程模型

v1 每项操作启动一个短生命周期进程，不使用共享常驻池。

- 每项任务独立 `0700` 工作目录。
- 全局最多两个外部提供方任务，同一压缩包仅一个修改任务。
- 不使用 shell；固定可执行文件；显式 argv；选项终止保护；最小环境。
- stdout/stderr 并发读取到有界环形缓冲；溢出终止任务，不以截断输出判断成功。
- 取消先温和终止，超时后强制终止；所有输出仅在暂存位置。
- 版本范围、架构、身份和输出协议均需匹配。
- 调度默认 FIFO；用户可以取消排队任务和把尚未开始的任务移到队首。v1 不提供暂停/恢复正在运行的编解码，只提供取消；崩溃恢复属于独立事务恢复语义。
- 外部工具默认使用 quiet/机器可控模式；stdout/stderr 环形缓冲只收集异常诊断，不承载条目清单或安全关键进度。正常进度来自 provider 的结构化回调、受控进度通道或文件系统计量；意外输出超限仍终止任务。
- libarchive 写盘不在主进程临时修改全局 `umask`。每个 libarchive 写入任务在独立短生命周期 helper 中以固定 `077` umask 启动，再由显式权限策略发布；因此不会与其他应用任务争用进程级 umask。
- 并发锁分为文档读快照与保存排他锁：浏览/搜索/预览/解压可共享同一已打开快照；保存获取排他锁，期间新的只读任务提示`正在保存，请稍后`，既有只读任务先完成或取消后才提交替换。

### 16.1 RARLAB

用户在`设置 > 外部工具`中明确选择或确认 `rar`：

1. 解析符号链接。
2. 验证常规文件、Apple Silicon、所有者为用户/root，且组/其他用户不可写。
3. 在执行前使用 Security.framework 静态代码 API 验证签名有效性、非 ad-hoc，并将签名链/Team ID 与项目维护的已验证 RARLAB 发布者清单匹配；若官方当前二进制不满足该条件，v1 RAR 创建保持禁用，不以版本字符串替代身份验证。
4. 显示许可证/外部依赖说明、签名身份和二进制 SHA-256，由用户确认。
5. 在只授权随机探测目录、无用户文件权限的隔离进程中执行创建、检测、解压缩探测并核对哈希；该步骤不证明后续输入可信，真实任务仍受通用进程模型和暂存发布限制。
6. 路径、文件身份、签名、版本或 SHA-256 变化时自动禁用，要求重新验证。

RAR 创建的通过条件必须全部满足：`rar` 返回成功；`rar t` 完整性检测无错误；用 RARLAB 自身解压到隔离目录后条目清单、大小和 SHA-256 与输入清单一致；再由固定版本 `7zz` 独立列举并解压比对一致。任何一步失败都不发布输出。Windows WinRAR 物理验收是 Direct/OpenSource 发布门槛，不是本机单次创建的静默替代项。

RARLAB 二进制文件不复制到项目、应用包、网站包或开源仓库。

## 17. DMG 与 ISO

DMG：只读、no-auto-open、no-browse 方式挂载，读取机器可解析结果并记录挂载身份；不运行内容；窗口关闭时卸载；失败可重试；启动时恢复应用遗留挂载。原始提取只有在夹具矩阵证明 UDZO/UDBZ/UDRW、加密与损坏 UDIF、sparse/sparsebundle、资源叉、符号链接、超大文件、取消和校验失败都不会越权或损坏数据后才启用；未通过时只提供只读挂载浏览。若 App Sandbox/hardened runtime spike 证明当前配置不能可靠挂载，则能力注册表把 DMG 标为`此构建仅支持识别，无法浏览磁盘映像`，不尝试放宽全局权限或伪装成可用。  
ISO：libarchive 只读浏览/提取，覆盖 ISO9660、Joliet、Rock Ridge、UDF 夹具。

## 18. 密码与钥匙串

- 密码使用安全输入框，不出现在日志、命令显示、错误详情或分析信息中。
- 默认只在当前操作内存中使用。
- 用户可选择`将密码储存在钥匙串中`。钥匙串密码项使用随机 UUID 主键；本地元数据只保存用户标签、安全作用域书签、卷/文件资源标识、创建时间和内容指纹，不保存密码。
- 打开时先解析书签并匹配文件资源标识；同卷重命名/移动后更新书签。精确内容指纹只用于识别未改变的复制件；编辑保存成功后在同一密码项上追加新指纹并淘汰旧的“当前位置”关联。
- 资源标识与指纹都不匹配时不自动尝试任何候选密码，提示重新输入并允许用户明确关联；网络卷、备份恢复和复制场景必须经过该保守分支。
- 错误状态区分：没有提供、密码错误、不支持的加密方式、文件损坏。
- ZipCrypto 的弱安全性在创建前明确提示。
- 密码以可控的字节缓冲传递，避免长期 Swift `String` 副本；C 适配器只在最短作用域创建本地缓冲，使用后显式清零。对 7zz/RARLAB，固定版本 provider 仅可使用工具自身的交互式密码模式：启动参数只含不带密码值的提示开关，helper 通过该子进程独占、不可继承的 stdin/伪终端写入一次密码字节并立即清零；禁止 argv、环境变量、普通/临时文件、剪贴板和 shell。若经 Xcode spike 证明某个固定版本无法在该合同下可靠工作，则该版本的加密操作保持禁用，不退回泄漏机制。不承诺对已被系统/框架复制的内存绝对擦除，但 crash/诊断收集必须排除密码字段。

## 19. Windows 与多语言互操作

内部合同：

- W0：Windows 11 Explorer 原生，未加密 Store/Deflate ZIP。
- W1：当前 7-Zip/WinRAR 可用的加密 ZIP/7z、分卷和 RAR。
- W2：TAR 系列/专业工具或命令行场景。

普通界面不用内部代码，只显示接收要求。

Windows 文件名规则基于 Microsoft 官方规则；每组件最多 255 UTF-16 code units。W0 使用 180 UTF-16 code units 的保守压缩包相对路径预算，并明确这是为常见提取目录预留空间，不等于所有环境保证。

物理验收必须覆盖 Windows 11 24H2 Explorer、当前 Windows 7-Zip、当前 WinRAR；对多语言名称、ZIP64、4 GiB 边界、分卷、加密、Mac 元数据清理和解压后哈希逐项证明。

## 20. Finder 与系统集成

- 文档类型关联和`打开方式`。
- Finder 快速操作：`创建归档`、`解压缩到此处`（安全选项与冲突时打开主应用）。
- Quick Look Preview Extension 只读、资源受限；不使用旧 `.qlgenerator`。
- Finder Sync 不用于普通压缩包菜单。
- Services/App Intents/Shortcuts 只暴露可安全、可解释的操作。
- 文档类型包含常见首卷/后续卷模式；分卷发现按格式规则和同目录授权进行，不依赖只注册主扩展名。

分卷发现先按 ZIP `.zNN`/`.zip`、7z `.7z.NNN`、RAR `.partNN.rar`/旧式 `.rNN` 的明确规则生成候选，再为每卷记录文件资源标识、大小、修改时间和 SHA-256 快照。操作开始前全部复核；发现同名身份变化、编号缺口、重复卷或越出已授权目录即停止并要求用户确认/重新选择，不把目录中“名字看起来像”的文件直接加入集合。

## 21. 操作记录与诊断

操作信息分三层：工具栏`当前操作`弹出层显示正在运行/排队任务；同一弹出层底部显示最近 10 项完成结果；菜单`窗口 > 操作历史`打开独立窗口并按保留策略显示更早记录。操作历史不作为默认导航侧栏。类型、文件显示名、时间、状态和可恢复操作一致，默认不永久保存完整路径。

错误详情包含：稳定错误代码、用户可读原因、建议操作、格式/引擎/版本、已脱敏路径和可复制诊断摘要。不得包含密码、密钥、完整私人路径或压缩包内容。

压缩包级注释和格式属性只在 provider 能无损、结构化读取时显示在`信息`检查器；v1 默认只读，不因一次普通内容编辑而丢弃。若目标格式保存会丢失它们，保存前列入元数据损失清单并要求另存为确认。

## 22. 错误分类与用户动作

| 分类 | 示例用语 | 主要动作 |
|---|---|---|
| unsupportedFormat | `暂不支持这种压缩包格式` | 了解详情 |
| unsupportedMethod | `压缩包使用了暂不支持的压缩方式` | 外部工具/取消 |
| passwordRequired | `需要密码才能继续` | 输入密码 |
| wrongPassword | `密码不正确` | 重新输入 |
| unsupportedEncryption | `暂不支持这种加密方式` | 了解详情 |
| corruptedArchive | `压缩包已损坏或不完整` | 检测完整性/尝试修复副本 |
| missingVolume | `缺少分卷文件` | 查找分卷/取消 |
| providerUnavailable | `所需的外部工具不可用` | 打开设置 |
| unsafePath | `部分项目包含不安全的路径` | 查看详情/取消 |
| resourceLimit | `预计解压内容超过安全限制` | 查看详情/明确覆盖（允许时） |
| nameConflict | `部分名称在目标位置会发生冲突` | 处理冲突 |
| sourceChanged | `原压缩包已被其他应用更改` | 重新打开/另存为 |
| diskFull | `磁盘空间不足` | 更换位置/清理/重试 |
| permissionDenied | `没有写入此位置的权限` | 另存为/选择位置 |
| canceled | `操作已取消，原压缩包未更改` | 关闭/重试 |
| helperFailed | `辅助进程未能完成操作` | 查看详情/重试 |

## 23. 性能预算（待基准验证）

- 所有编解码和摘要工作不在 MainActor。
- 100,000 条目压缩包在目录可用后 2 秒内出现首个可操作列表。
- 索引完成后的搜索反馈目标 100 ms。
- 列表滚动目标 60 fps。
- 进程内取消确认目标 1 秒；外部进程 3 秒后升级终止。
- 预览缓存每条目 256 MiB、每窗口 1 GiB、30 秒。
- 内存、索引和预览按条目规模有显式计量；不能把整个大压缩包内容读入内存。

这些是验收假设，必须在目标 Mac 上用 Instruments/signpost 实测并调整，不能预先宣称达标。

## 24. 可访问性

- 所有图标按钮有简体中文可访问性标签与提示。
- VoiceOver 顺序：窗口身份、工具栏、侧边栏、内容、检查器、状态/编辑栏。
- 表格列标题、排序和层级状态可读。
- 完整键盘操作覆盖打开、导航、选择、预览、添加/移除/重命名、解压缩、保存和取消。
- 不只用颜色表达加密、错误、暂存或选择。
- 支持降低透明度、增强对比度、减少动态效果和系统强调色。
- 工具栏选择、列表选择和焦点使用系统 `controlAccentColor` 语义，不硬编码品牌色。
- 200% 文本/显示缩放与长繁体/英文字符串不能截断核心操作。

验收指标：所有图标按钮 100% 有中文标签/提示；可交互列表行 100% 可由 VoiceOver 读出名称、类型、层级、选择和加密状态；进度开始、10% 级变化、完成、失败和取消有节流公告；仅键盘可以完成打开、导航、预览、解压、创建、暂存编辑、保存和取消。自动化运行 `XCUITestAccessibilityAudit` 并保留人工 VoiceOver 录屏/问题清单。

## 25. 应用图标设计简报

使用 Icon Composer 和最新 macOS 图标系统；Apple Silicon only 不影响图标资源。

概念：一个简化的“归档容器 + 可查看内容层”符号，强调打开/查看/整理，不使用传统夸张拉链、纸箱或 Windows 风格压缩图标。轮廓在 16/32 pt 仍可识别，避免细小文件列表。需要验证浅色、深色、着色与透明外观，以及 Dock、Finder、设置和打开方式尺寸。

图标需单独生成 3 个方向并经用户选择、MiniMax/GLM 语义检查、Gemini/Kimi 视觉检查和 Codex 小尺寸实机验收。

## 26. 构建配置与许可证

### Local

ad-hoc/local signing；开发初期可发现用户本地经过验证的 `7zz`/RARLAB；允许本地构建固定 `7zz`。不上传。

### Direct

固定 ARM64 helper；Developer ID、hardened runtime、公证、嵌套代码签名、干净 Mac 验证。主应用最小授权仅包含确有实现证据的用户选择文件读写和必要的应用组；禁用 JIT、动态库验证放宽、任意文件与不必要网络。最终 entitlement 由 Xcode 安全 spike 证明后冻结。捆绑 7-Zip 前提供对应源代码/精确 commit、构建脚本、修改记录、可替换或重新构建说明，以及 LGPL/BSD/UnRAR 通知；RARLAB 始终外部。

### OpenSource

锁定依赖 commit 与校验和，记录 Xcode/SDK/Swift 版本、编译参数、代码生成输入、provider 构建脚本和已知非确定性来源；首版只承诺“可审计、文档化构建”，通过双机字节比对前不宣称字节级可复现。无专有 RAR 二进制；应用开源许可证由用户后续决定；生成 SPDX SBOM 和第三方通知。未经命令不创建远程/上传。

### 安装、升级与卸载

Local 直接复制 `.app` 到 `/Applications` 或用户应用目录；Direct 使用只包含已公证 `.app` 与 Applications 快捷方式的只读 DMG。首次启动只显示格式能力和外部工具状态，不索取无关权限。升级保留 String Catalog、设置与钥匙串 schema 迁移版本，迁移失败回滚配置副本而不影响压缩包。卸载为退出应用后移至废纸篓；帮助页列出可选的应用支持、缓存和钥匙串清理入口，默认不自动删除用户数据。

所有构建生成组件清单：名称、版本/commit、源码 URL、许可证、补丁、构建参数、校验和、捆绑/外部状态。

## 29. 设计验收场景

主应用是否沙盒化不改变扩展边界：Quick Look 与 Finder/App Intents 扩展使用各自独立 App Sandbox、只读/用户选择授权和独立容器；扩展不得执行 7zz/RARLAB、不得获得主应用任意文件权限，也不通过共享可执行代码绕过沙盒。主应用与扩展只经版本化、类型化的 App Group 请求/结果文件或系统 extension API 交换最小元数据；请求含随机 ID、输入书签/只读文件协调信息、期限和签名/HMAC，主应用重新授权并重新验证后才执行。扩展失败只回退为`在归档工作台中打开`，不放宽 entitlement。
